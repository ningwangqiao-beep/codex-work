# Read-only shanten integration review

Read hand_analysis.py, selfplay.py, observations/public.py and round2_data_shanten_eval.py. No running dependency or process modified; bounded evaluation left intact.

Public counts: integration correctly counts unclaimed discards + meld tiles + one physical archived winning tile, masks opponent concealed kongs (-1 excluded), includes own concealed kong faces, excludes own concealed hand from public list. Candidate discard moved from own hand to pub exactly once. Thus known-count remains constant and fifth-copy checks remain valid. Multiwinner action history can repeat the same tile, but physical count uses wins archive rather than history, avoiding duplicate counts. No opponent hidden hand input into callback.

Effective draws: remaining=4-known is an observable upper bound, not actual wall inventory: tiles concealed in other hands, hidden kongs or exited winners remain unknown. Summing remaining is a public ukeire heuristic, not calibrated draw probability. This must be labeled visible-unseen count. Structural shanten intentionally ignores dead waits; it can rank a zero-live-out wait as distance 0 while live alternatives have greater distance. This is a policy tradeoff, not proof of optimality. Open-meld validation assumes prior engine enforcement; independent callers cannot validate meld identities from count alone.

Algorithm: DFS enumerates all disjoint meld/head/taatsu/leftover branches. Formula caps taatsu by remaining meld slots; seven-pairs quad counts two pairs to match this engine. Removing missing-suit tiles treats them as obligatory future discards, not exact constrained expected draws. -1/core equivalence is useful but insufficient to prove positive shanten distances; add independent exhaustive low-tile/open-meld oracle before strong optimal-distance claims. No evidence from this review of a direct win/nonwin contradiction.

Evaluation design: all four seats and both policies included per completed seed, and bootstrap resamples complete seed groups, appropriately accounting for within-seed pairing. However timeout/error catches all exceptions, reports partial prefix seeds and drops incomplete seed groups. Completed-prefix result is not full prespecified 20-seed result; wall-clock censoring correlates with game complexity/shanten cost. Require status=completed and complete_seed_groups==games before headline claim; incomplete result is throughput/debug evidence only. Timeout checked only on shanten callback entry, not baseline game loop or DFS inner loop, so not a hard global bound. Different policies consume different random-call paths; same initial seed is paired deal/seed, not aligned stochastic opponent trajectories.

Strength boundary: policy changes discards only; engine still automatically chooses legal wins and greedy kongs/peng via shared driver. Shape callback differs slightly from built-in shape tie randomness, but is explicitly fixed across seats; results compare these exact callbacks. 20 seeds/80 seat pairs is a small exploratory sample with potentially broad CI, not final deployment evidence. No tuning based on this set should follow while continuing to call it an untouched final test.
